# spec v0.2.0

## New: `BeforeEach`, `AfterEach`, `JustBeforeEach`

`S.BeforeEach`/`S.AfterEach` (and `Suite.BeforeEach`/`Suite.AfterEach`) are
the real names for what `Before`/`After` already did -- run before/after
each spec in the group or suite, at every nesting level, with no shared
state between runs. The behavior didn't change; the name now matches what
Ginkgo, RSpec, Jest/Mocha, and Kotest already call the same hook.

`S.JustBeforeEach` is genuinely new: it runs after every `BeforeEach` at
every nesting level has run, immediately before the spec itself. It lets a
suite separate "what varies" (an ordinary `BeforeEach` in each nested
`context`) from "the action under test" (declared once, in a parent),
instead of duplicating that action in every leaf or invoking a `subject`
closure explicitly in each spec. Same role as Ginkgo's own
`JustBeforeEach`.

```go
context("#divide", func() {
    var numerator, denominator, result int
    it.JustBeforeEach(func() {
        result = calculator.Divide(numerator, denominator)
    })

    context("dividing evenly", func() {
        it.BeforeEach(func() { numerator, denominator = 10, 2 })
        it("returns the quotient", func() { ... })
    })
})
```

See the README's `JustBeforeEach` section and `docs/COWORK.md` for the
full reasoning, including why this shipped as a deprecation rather than a
breaking rename (below).

## `Before`/`After` are deprecated, not removed

`Before`/`After` still work -- they're now thin aliases for
`BeforeEach`/`AfterEach`, marked with the standard Go `// Deprecated:`
godoc comment. No consumer's build breaks on this version. What changes:
`staticcheck`'s `SA1019` check (part of `golangci-lint`'s default linter
set, so nothing extra to configure) flags any `it.Before(...)`/
`it.After(...)` call site as deprecated-symbol usage the next time
`make lint`/`make check` runs, and most editors (gopls and others) render
the deprecated symbol with a strikethrough. Each consumer can migrate to
`BeforeEach`/`AfterEach` on its own schedule rather than all at once.

## Upgrading

No breaking changes -- every existing `it.Before(...)`/`it.After(...)`
call site keeps compiling and passing. `BeforeEach`, `AfterEach`, and
`JustBeforeEach` are additive; migrating off `Before`/`After` is
recommended (lint will remind you) but not required.

Consumers pinning `github.com/sclevine/spec` directly and wanting this
fork's additions need a `replace` directive, since this fork keeps
upstream's module path unchanged:

```
replace github.com/sclevine/spec => github.com/woodie/spec v0.2.0
```
